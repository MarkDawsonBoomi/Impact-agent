Why live lookup?

  • Always current: reads Boomi as it is right now
  • Nothing to schedule, store, or keep in sync
  • Accurate: the process follows the dependencies in code; the agent only explains them
  • Uses a process + OpenAPI tool, because an Integration tool returns only run status, never the report

Trade-offs

  • Answers take seconds, not milliseconds
  • Sees Boomi integrations only
  • Large accounts: watch Platform API rate limits
  • "Ideal world" extras (severity, owners) come in a later phase

Other ways to avoid a crawler

Register at deploy timeThe CI/CD pipeline records each integration's systems when it's deployed, so the catalog updates itself.
Reuse an existing data catalogIf the organization already has one, the agent queries it through an OpenAPI or MCP tool.
Snowflake's own lineage viewsQuery ACCESS_HISTORY live to find dashboards and apps that use Snowflake outside Boomi.
Owner-maintained registryTeams list their own integrations (e.g. in DataHub). Simplest option, but it can go stale.
Prove it: ask the agent about the recent real migration and compare its answer with the impact list the team built by hand.
